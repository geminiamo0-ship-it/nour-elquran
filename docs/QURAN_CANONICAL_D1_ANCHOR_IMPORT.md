# P0-2: canonical Hafs anchors — verified generation only (#147)

The learner-private D1 API introduced in #145 refuses notes/highlights unless the imported edition and matching ayah/word anchors exist. **No fake Quran word counts, guessed page numbers or imported real learner data.** This follow-up implements a review-only canonical importer and GitHub Actions evidence, not a live D1 deploy.

## Independent pinned sources

1. The already dedicated `noor-quran-assets.geminiamo0.workers.dev/quran/hafs/v1.1.1/manifest.json` published by the isolated Santoreno Noor Quran R2 workflow, citing pinned `quran-ws/quran-svg@9fc0c87`. The importer verifies exactly 604 page JSONs against manifest SHA-256 hashes, 114 surah counts and 6236 unique ayah polygons. Source manifest must have exactly 1324 listed assets, including corresponding SVG files, two index files, and 114 chapter files. **It does not download or redistribute copyrighted page SVG or Quran text into the repository.**
2. Independently pinned `quran-ws/quran-text@80361413c304107801895ba303ca01971f20bfe4`, `data/mushaf/hafs.json`, with 6236 Kufi-count ayahs, 77432 words, source-published ayah and page word boundaries. For every ayah, number of source words = the difference between adjacent **provided** boundaries, and marker page = the source page containing the last printed word. No split/tokenized Arabic generated by our code.

The verifier **refuses output** when edition, SHA, source revision, surah/ayah counts, word boundaries, SVG page of ayah medallion or verse keys disagree. A mismatch is a real release **blocker**: manually investigate the differing Quran editions/layout sources instead of skipping checks or inventing a word count.

## Exact, non-mutating workflow

- `.github/workflows/quran-anchor-verify.yml` runs on changes to the importer/tests, and can be manually dispatched. It runs Python synthetic tests, independently downloads the public published source, and uploads `verified-quran-anchors.sql` (6236 insert statements) + `verified-quran-anchors-evidence.json` with source/manifest hashes only after all checks. These are **review-only output artifacts**. No `wrangler d1 execute --remote`, Cloudflare secrets, remote database IDs, mutations or tenant data touched.
- Local dry-run: `python3 -m unittest discover -s tests/quran -p 'test_*.py' -v`; generate after verifying public sources: `python3 scripts/noor_quran_anchor_import.py --output-dir /tmp/quran-anchors`.
- For drift-protected repeat runs supply `--expected-manifest-sha256 <64-character-reviewed-hash>`; pin both release commit and reviewed manifest SHA in an approved deployment plan before remote Staging.
- Verify source artifact/commit SHA from Actions, independently approve SQL and evidence, snapshot isolated staging D1, then apply using an operator-reviewed process; afterward cross-check 114/6236/604/77432, foreign keys, edition hash and the sample first/last metadata. Do not activate feature flags until independent authenticated two-account, two-device Chrome and mobile QA passes.

**Important:** This script is not an automatic D1 migration; an edition row without 6236 valid anchors is **not** a completed release. The private client uses a memory-only pending queue; browser crash before server ACK may lose pending operations.
